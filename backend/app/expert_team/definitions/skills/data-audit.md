# 数据检核 Skill (data-audit)

> 查实真的专用 Skill，覆盖数据质量检核和多分析师产出一致性检核。

## 触发词
| 场景 | 动作 |
|------|------|
| 主理人要求检核 | 执行 Phase A + Phase B |
| 多分析师产出自动触发 | 执行口径一致性检核 |

## 输入
- 待检核的分析结果（来自分析师回传）
- 原始查询参数（year/month/entity/SQL）

## 输出
- 按 K5 output-format-spec.md 的检核报告格式

## SOP（5步）

### 步骤1：接收检核请求
- 确认待检核的产出来源（哪个分析师）
- 获取原始查询参数

### 步骤2：Phase A 结果检核
| 检核项 | 方法 |
|--------|------|
| SQL语法 | 核对查询语句是否合法 |
| 计算逻辑 | 核对公式是否与 K2 data-dictionary 口径一致 |
| 同环比 | 验算同环比计算是否正确 |
| 数量级 | 检查数值是否在合理范围（如销售额不应为负） |
| 时效性 | 检查数据时间是否为最新可用 |

### 步骤3：Phase B 异常检查
| 检核项 | 方法 |
|--------|------|
| 空值率 | 检查关键字段空值比例 |
| 枚举合法 | 检查维度值是否在 K1 枚举范围内 |
| 口径一致 | 多分析师产出间是否有矛盾 |
| 跨分析师一致 | 多人引用同一指标时口径是否统一 |

### 步骤4：判定
- 全部通过 → "通过"
- 有风险但可接受 → "标注风险通过"
- 有错误 → "不通过"+修正建议

### 步骤5：输出检核报告
- 按 K5 检核报告格式输出
- 不通过时明确修正项

## 约束
- 只做诊断+记录，不做修改
- 不代写分析师产出
- 检核依赖 K1（表结构）和 K2（口径定义）作为参照标准
