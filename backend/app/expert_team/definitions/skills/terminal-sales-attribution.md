# 终端销售额归因分析

## 业务语境

当需要回答"本月销售变化的原因是什么"时使用。
核心逻辑：将销售额变化分解到区域、渠道、产品三个维度，计算各子选项的销售变化贡献率，识别增长主因和下滑风险。

常见触发场景：月度经营分析会、区域巡访前准备、渠道健康度排查、新品上市效果评估。

## 执行流程

### Step 1：获取归因数据

运行归因脚本获取三维度归因表：

```bash
python3 ${CODEBUDDY_SKILL_DIR}/scripts/attribution.py \
  --data <数据文件路径> \
  --month <YYYYMM> \
  --entity-type <分析对象类型> \
  --entity-name <分析对象名称> \
  --drill-level <1或2>
```

**分析对象类型**：
- `nation`（全国）、`region`（大区）、`province`（省区）、`district`（地区）
- `channel`（渠道等级）、`chain`（连锁系统）、`store`（门店）
- `product_circle`（产品圈层）、`product_series`（产品系列）、`product_segment`（商品段位）

**下探层数**：
- `1` = 下探一层（默认）
- `2` = 下探两层
- `0` = 自动判断（子项<5个时自动下探两层）

### Step 2：读取并解读归因结果

脚本输出包含：
1. **总体指标**：本月销售额、前3月月均、变化值、环比变化率、趋势（增长/下滑）
2. **三维度归因表**：区域、渠道、产品各自的子选项归因
3. **关键发现**：正向贡献TOP3 + 反向拖累TOP3

### Step 3：综合判断

根据归因表做综合判断，输出归因结论。

## 判断标准

### 确定性规则（脚本已计算）

贡献率含义：
- **正向贡献率** > 20% → 该选项是增长的主要驱动力
- **反向贡献率** < -10% → 该选项是需要关注的风险点
- **贡献率接近0** → 该选项对整体变化影响不大

### 判断边界（需要灵活处理）

**边界1：总体变化不显著时**
- 环比变化率在 ±2% 以内时，贡献率的绝对值会被放大
- 此时需要标注："总体变化不显著，贡献率参考意义有限"
- 重点看变化值的绝对金额而非贡献率

**边界2：贡献率之和不为100%**
- 正向贡献率和反向贡献率各自独立计算，加总不等于100%
- 正确理解：正向TOP3贡献率之和 = 正向变化的集中度；反向同理
- 集中度越高（如TOP1贡献率>50%），说明原因越集中，越容易定位

**边界3：多维度交叉判断**
- 不应只看单一维度。如果某个选项在多个维度都出现在TOP3，说明它是核心因素
- 示例：品牌产品在产品维度贡献56%，同时RKSC（品牌产品主渠道）在渠道维度贡献88% → 品牌产品通过RKSC渠道驱动的增长是本月核心动因

**边界4：分析对象为子对象时（多轮追问）**
- 当用户追问"RKSC的增长动因"时，需要加 `--compare-with-parent` 参数
- 脚本会输出"与全国基准对比"表，判断某个选项是否对该分析对象"超指数"重要
- "超指数" = 该选项在分析对象内的贡献率高于全国水平 → 说明它对该对象特别重要

## 多轮追问逻辑

```
用户："本月全国销售变化原因"
  → 运行nation归因 → 识别RKSC贡献率88%
用户："RKSC的增长动因是什么"
  → 运行channel归因(entity=RKSC, compare-with-parent)
  → 识别RKSC下各区域/产品的贡献率 + 与全国基准对比
  → 如果某选项"超指数"，说明它对RKSC特别重要
用户："那品牌产品呢"
  → 运行product_circle归因(entity=品牌产品)
  → 识别品牌产品下各产品系列/渠道/区域的贡献率
```

## 与邻近skill的区别

- **动销率分析**：看"铺了但卖不动"的渠道推力问题，本skill看"销售额变化的结构性原因"
- **铺货率分析**：看"有没有到终端"，本skill看"到了终端后销售额的变化贡献"

## 输出约束

- 必须包含三个维度的归因分析（区域/渠道/产品）
- 必须识别正向贡献TOP3和反向拖累TOP3
- 贡献率必须标注是"对谁的贡献率"（对全国/对北一区/对RKSC）
- 如果是多轮追问，必须对比分析对象内贡献率与全国贡献率的差异
- 禁止只给数字不给结论——必须说清楚"这意味着什么"
- 禁止输出空洞结论如"各区域表现差异较大"、"建议关注下滑区域"
