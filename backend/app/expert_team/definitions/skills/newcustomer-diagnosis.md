# 婴配粉新客来源智能诊断

## 业务语境

回答"新客结构是否健康、哪里出了问题"。核心问题：各段位的新客占比与销售占比是否匹配？如果不匹配，是哪个区域+哪个渠道拉起来的？

常见触发：月度经营分析会前准备、区域巡访前新客健康度排查、大区负责人追问"我这个区新客有没有问题"。

---

## 触发词定义

| 用户表达 | 触发模块 |
|---------|---------|
| 简单提问、"看看"、"查一下"、"怎么样" | 模块1（快速诊断）|
| 明确说"报告"、"全面分析"、"完整分析"、"用于汇报" | 模块2（深度报告）|
| 报告后追问"怎么办"、"有什么建议"、"原因是" | 模块3（诊断建议）|

**默认进入模块1**。模块2需要用户明确触发词，避免LLM误判意图。

---

## 工作流程（三模块）

### 模块1：快速诊断（轻量化）

**触发**：默认模式，用户简单提问时。

**流程**：
1. 识别分析对象（全国/大区/省区）和关注段位
2. **轻量化确认**（一句话）："我将用overview分析{对象}的{段位}新客结构，继续？"
3. 调用 Python 工具箱（**优先只用 overview**，必要时才调 segment-gap/cross）
4. 输出速览版（对话中直接输出，3-5句话 + 简表）
5. 提示用户："需要完整报告？回复'出报告'"

**输出格式**：
```
## 新客结构速览：{分析对象}

**核心发现**：
- {段位}差值{差值}pp（{状态}），{一句话解读}
- {如有失衡}主因：{区域}·{渠道}（贡献{贡献度}pp）

> 需要完整报告？回复"出报告"
```

---

### 模块2：深度全面报告（严格模板）

**触发**：用户明确说"报告"、"全面分析"、"完整分析"。

**流程**：
1. 识别分析对象、维度、段位
2. **输出分析计划**（指标、维度、目的）→ 用户确认
3. 读取 `references/report-template.md`（含【严格遵守】标注）
4. 按5页结构执行（总揽 → 交叉归因 → 维度差异 → 下钻定位 → 诊断结论）
5. 读取 `references/reasoning.md`（推理框架）和 `references/knowledge.md`（知识库）
6. 产出完整 Markdown 报告文件

**关键约束**：
- 【严格遵守】部分：报告结构、数据数字、章节顺序必须按模板
- 【推理介入】部分：分析深度、挖掘方向、解读逻辑可灵活调整
- 数字必须来自 Python 工具，LLM 不自行计算
- 报告产出后自动提示进入模块3

**报告路径**：`{工作目录}/新客诊断报告_{{entity_name}}_{{YYYYMMDD}.md`

---

### 模块3：诊断建议互动（模块2的后续）

**触发**：模块2产出报告后自动进入，或用户追问"怎么办"。

**流程**：
1. 基于模块2的分析发现，结合推理框架 + 知识库 + 记忆库，输出诊断建议
2. 与用户互动，引导用户补充判断
3. 多轮追问，每轮可实时调用 Python 工具补充数据
4. **识别可记录内容** → 询问用户"是否将这条判断加入记忆库？"
5. 用户确认后，写入记忆库（ `~/.workbuddy/memory/skill-memory/newcustomer-diagnosis.md`）

**记忆库更新时机**：每次互动结束后，将用户的业务判断、对数据的理解、修正的推理结论写入记忆库。

## Python 工具箱

以下工具可独立调用，LLM 根据推理需要自行选择。

**数据要求**：
- 格式：`.xlsx`
- 必含列：大区、省区、段位、大系统渠道名称、连锁系统名称、首购新客数、终端销售金额

## 输出约束

- 报告阶段的数字必须来自 Python 工具，不能由 LLM 自行计算
- 差值必须标注方向（+表示新客占比高，-表示销售占比高）
- 交叉归因必须说明贡献度含义（+2.1pp = 为整体差值贡献了2.1个百分点）
- 下钻到省区/终端时必须说明"为什么下钻到这里"
- 禁止只给数字不给结论——必须说清楚"这意味着什么"
- 禁止输出空洞结论如"各段位差异较大"、"建议关注1段"
- 推理阶段的建议必须是可操作的，如"辽西·福娃孕婴需重点排查1段获客转化"
- 阈值是辅助参考，LLM 可以根据业务场景灵活判断，但需说明为什么偏离阈值建议
- 占比之和=100%：1段差值+23pp 意味着2/3段必然有负差值，需在解读中提醒用户
- **数据展示必须完整**：尽可能列出所有选项/行/类别；仅当选项超过15个时可考虑筛选展示；如做了筛选或省略，必须说明(a)总共有多少个(b)展示了多少个(c)筛选标准和原因；不得默认只展示"显著的"或"异常的"而不说明
- **Comment写作规范**：报告中的解读/Comment必须遵循：(1) 每个观点一句话 (2) 先解读数据再发表观点（数据→判断） (3) 用业务角度解读，不教人读表
- **归因边界**：差值（新客占比-销售占比）只反映结构差异，不能直接归因到某个业务动作。例如：2/3段销售占比高于新客占比，只能说明"老客占比较高"，不能推断为"复购贡献大"或"拉新不足"——具体原因需交叉验证后才能判断
- **禁止硬编码维度值**：报告中的任何维度（大区、省区、渠道、段位等）的值，必须从数据源动态读取，不得凭行业常识或经验硬编码。行业知识可能过时、可能不适用于当前数据源，用假设代替数据会导致遗漏或编造不存在的维度值
- **着色规则（偏离整体着色法）**：差值绝对值受段位特性影响大（1段天然+20pp左右），直接对差值着色无区分度。采用"偏离整体"着色：某维度值的差值与全国同段位差值的差，反映该维度是否比整体更失衡。规则：|偏离|>3pp🔴明显偏离 / 1~3pp🟡轻度偏离 / ≤1pp无色 / -3~-1pp🟢偏低 / <-3pp🟩明显偏低。数据支撑：大区1段偏离范围-3.9~+3.0pp，3pp阈值可区分出南二区(-3.9)、北一区(+3.0)等明显偏离项
- **连锁系统分析范围**：只分析 KSC/NKA/RKSC 的连锁系统。省区常规的连锁系统为零散单体（2000+个），分析价值低，默认排除

## 与邻近 skill 的区别

- **terminal-sales-attribution**：回答"销售额变化的原因"，看环比变化贡献率。本 skill 看"新客与销售的结构性矛盾"，看截面占比差值
- **动销率分析**：看"铺了但卖不动"。本 skill 看"新客来了但没转化成等比例销售"

---

## 分析限制

1. **当前仅支持离线 Excel 数据源**：需先导出 Excel
2. **不支持跨月对比**：当前仅分析单月截面，环比趋势需 V2
3. **终端级诊断精度有限**：终端行数据少时判断可能不稳定
4. **排除 OTC 渠道**：OTC 体量太小，默认排除
5. **KSC 合并为管理口径**：KSC 东区+KSC 西区→KSC
6. **段位占比之和=100%**：1段差值+23pp 意味着 2/3 段必然有负差值，这是数学必然而非独立问题
7. **连锁系统分析范围**：只分析 KSC/NKA/RKSC 的连锁系统；省区常规为2000+零散单体，分析价值低，默认排除
