# 婴配粉区域销售智能诊断

## 业务语境

回答"哪个区域销售有问题、问题出在渠道还是产品"。核心问题：各区域销售额/达成率是否健康？异常区域的根因是渠道结构问题还是产品布局问题？

典型场景：月度经营分析会前区域诊断、某大区连续下滑专项分析、双周复盘材料准备。

---

## 触发词定义

| 用户表达 | 触发模块 |
|---------|---------|
| 简单提问、"看看"、"查一下"、"怎么样" | 模块1（快速诊断）|
| 明确说"报告"、"全面分析"、"完整分析"、"用于汇报" | 模块2（深度报告）|
| 报告后追问"怎么办"、"有什么建议"、"原因是" | 模块3（诊断建议）|

**默认进入模块1**。模块2需要用户明确触发词，避免LLM误判意图。

---

## 工作流程（三模块）

### 模块1：快速诊断（轻量化）

**触发**：默认模式，用户简单提问时。

**流程**：
1. 识别分析对象（全国/大区/省区）和分析时间
2. **轻量化确认**（一句话）："我将诊断{对象}{时间}的区域销售，继续？"
3. 调用 Python 工具箱（优先 `overview`，必要时 `region-detail` / `channel-breakdown`）
4. 输出速览版（对话中直接输出，3-5句话 + 简表）
5. 提示用户："需要完整报告？回复'出报告'"

**输出格式**：
```
## 区域销售速览：{分析对象}，{时间}

**核心发现**：
- 总销售额{金额}，环比{变化}，达成率{数值}
- {异常数}个大区异常：{大区名}({原因简述})
- 最大拖累：{渠道/产品}，贡献度{数值}pp

> 需要完整报告？回复"出报告"
```

---

### 模块2：深度全面报告（严格模板）

**触发**：用户明确说"报告"、"全面分析"、"完整分析"。

**流程**：
1. 识别分析对象、分析时间
2. **输出分析计划**（指标、维度、目的）→ 用户确认
3. 读取 `references/report-template.md`（含【严格遵守】标注）
4. 按7模块结构执行（总览 → 区域总览 → 省区下钻 → 渠道分析 → 产品分析 → 交叉分析 → 异常归因）
5. 读取 `references/reasoning.md`（推理框架）和 `references/knowledge.md`（知识库）
6. 产出完整 Markdown 报告文件

**关键约束**：
- 【严格遵守】部分：报告结构、数据数字、章节顺序必须按模板
- 【推理介入】部分：分析深度、挖掘方向、解读逻辑可灵活调整
- 数字必须来自 Python 工具，LLM 不自行计算
- 产品系列仅展示 Top 10，其余合并为"其他系列"
- 报告产出后自动提示进入模块3

**报告路径**：`{工作目录}/区域销售诊断报告_{entity_name}_{YYYYMMDD}.md`

---

### 模块3：诊断建议互动（模块2的后续）

**触发**：模块2产出报告后自动进入，或用户追问"怎么办"。

**流程**：
1. 基于模块2的分析发现，结合推理框架 + 知识库 + 记忆库，输出诊断建议
2. 与用户互动，引导用户补充判断
3. 多轮追问，每轮可实时调用 Python 工具补充数据
4. **识别可记录内容** → 询问用户"是否将这条判断加入记忆库？"
5. 用户确认后，追加到 `references/memory.md`

## 知识库与记忆库

### 知识库 `references/knowledge.md`

静态领域知识，条目化格式（K-####编号）。

**LLM 权限**：可在互动中建议"是否将这条判断加入知识库"，用户确认后写入。

**读取时机**：模块2和模块3开始前读取。

### 记忆库 `references/memory.md`

**写入时机**：模块3每次互动结束后，将本次用户反馈写入。

**读取时机**：模块2和模块3开始前读取，作为推理的信息基础。

## 输出约束

### 报告呈现
- **禁止使用模块编码**：面向用户的报告和对话中，章节标题必须使用中文描述名（如"渠道结构分析"），严禁使用 M1/M2/M3/M4 等编码。模块编码仅限 skill 内部文档和模板引用，不是给用户看的。违反此规则会导致用户看不懂报告结构。
- 报告阶段的数字必须来自 Python 工具，LLM 不自行计算
- **禁止硬编码维度值**：大区、省区、渠道、产品系列等所有维度值必须从数据源动态读取
- **全量展示原则**：默认展示所有维度值；仅当选项超过 15 个时可筛选，且必须说明(a)总数(b)展示数(c)筛选标准
- 产品系列：63 个系列→仅展示 Top 10，其余合并为"其他系列"（1行）

### Comment 写作
- 每个观点一句话，先数据后判断（数据→判断）
- 用业务语言解读，不教人读表
- 禁止空洞结论："各区域差异较大"、"建议关注"——必须说清"这意味着什么"
- 禁止重复表格中已有的数字

### 归因边界
- 环比变化/贡献度反映变化方向，不能直接归因到团队能力或管理问题
- "南二区环比 0.94（低于近三月均值 6%）" → 可以说"下滑"，不能说"南二区团队能力不足"
- 渠道占比变化 → 可归因到"渠道策略调整"，不能说"电商抢走了线下"
- 无法验证的假设必须标注"待验证"

### 维度约束
- KSC 东区和 KSC 西区是独立渠道值，**不得合并**为"KSC合计"
- 渠道共 5 个固定值：省区常规、RKSC渠道、KSC东区、KSC西区、NKA渠道
- 产品系列级别**无法计算达成率**（目标表无产品维度）

### 异常判定阈值（参考值，LLM 可灵活判断）

> 环比定义为"本月日均销售额 / 近三月日均销售额"。比值 > 1.0 = 跑赢均值，< 1.0 = 跑输。

- 🟡 预警：环比 < 0.90 且达成率 < 80%
- 🔴 严重：环比 < 0.80 且达成率 < 60%
- 省区下钻触发：环比 < 0.95 或达成率 < 85%

## 与邻近 skill 的区别

- **terminal-sales-attribution**：回答"销售额变化的原因"，看环比变化贡献率，聚焦归因。本 skill 看"区域销售健康度全景"，聚焦诊断
- **newcustomer-diagnosis**：回答"新客结构是否健康"，看新客/销售占比差值。本 skill 看"销售额/达成率的区域分布"

---

## 分析限制

1. **数据源为 AnalyticDB 直连**，需 datachat-query skill 可用
2. **产品系列 63 个**，M5 仪展示 Top 10 + 合并
3. **产品级别无达成率**：目标表缺少产品维度
4. **缺少门店粒度**：无法分析单店产出变化
5. **缺少竞品数据**：无法归因竞品动作
6. **省区常规渠道口径差异**：该渠道可能为经销商出库口径而非终端动销
7. **渠道共 5 个固定值**：如未来新增渠道类别，需更新脚本常量
